# 可观测性设计要求

设计新增或改变运行入口、异步或后台工作、外部事件处理、并发边界时，说明以下内容。纯进程内数据结构等不涉及外部效果或遥测的设计，可以注明不适用及原因。

1. **关联上下文**：明确每个边界的逻辑操作范围，可用的 request、session、trace、job、principal 或 resource 等标识，建立位置及传递方式。没有操作标识时，说明为何属于系统级工作，以及可用于关联的稳定组件或资源信息；需要提前解析标识时明确解析位置。
2. **执行边界**：列出新增的延迟、脱离、调度和并行执行机制。分别说明关联与 tracing 上下文如何保留、工作由谁管理、生命周期如何结束、取消与失败如何传递或报告，以及避免丢失上下文的标准抽象或约束机制。
3. **错误路径**：每条记录遥测的新失败路径使用结构化、脱敏的错误表示，包含错误类型或类别、有用的原因、受影响组件、操作阶段和可用关联标识。说明这些字段经过传输与存储后仍如何查询，以及相关限制。遥测增强不能改变授权、校验或其他安全决定，也不能输出敏感值。
4. **候选版本验证与运行排查**：在验收者控制的环境中运行指定提交，验证事件、关联标识、错误分类和敏感信息排除。提供可复用的查询、过滤条件、trace 搜索或等价步骤，供后续运行排查使用；生产环境中的实际观察不作为代码验收的隐含完成条件。
