# 评审执行要求

## 选择可用的独立评审能力

使用当前环境实际可调用的独立代理或外部 CLI。选择外部 CLI 前，检查程序、指定 agent 及其依赖是否可发现和运行；磁盘上存在配置不等于当前宿主能够加载它。参数与模型选择根据本机帮助和当前配置确认，不依赖固定工具名或旧命令模板。当前已作为独立 reviewer 被调用时，可以直接承担适合的视角，不递归调用同一个评审协调入口。

默认继承会话模型。用户要求多模型时，确认实际选择了不同模型，并记录参与者；不能用多个同模型角色满足多模型要求。需要的能力不可用时说明缺口，替代方案按已有授权和验收要求选择，不能静默降低必需标准。

## 明确输入、权限与结果合同

向 reviewer 提供设计材料的准确位置和版本标识或内容 hash、确认范围与设计阶段、相关 schema、协议、接口或共享类型定义及原始证据，以及要检查的风险。要求其独立判断，不预置作者希望得到的结论。

评审使用只读的设计与代码输入，只写约定的评审输出。需要保存文件时明确允许的目录和结果路径；也可由父代理保存返回的文本。禁止修改设计、业务代码、Git 状态或外部资源。权限仅覆盖这项评审所需能力，非交互执行不意味着开放所有工具、路径和 URL。

沿用当前认证，不无条件覆盖凭据环境变量，不把认证失败替换为空值；敏感数据不得进入报告或原始日志。

统一接收外部 CLI 与本地代理的结果：

- 被审查的文档版本、范围及实际 reviewer 和模型。
- 是否完整结束、当前 verdict 和结果位置或内容。
- Finding 的严重程度、具体问题、依据，以及范围内修正、延后或不成立的判断。
- 尚需决策、缺失的证据及各 reviewer 的重要分歧。

读取文件前验证它是本次运行针对当前输入的完整结果，不能把旧文件、部分输出或进程启动成功当作评审完成。临时报告与长期材料按项目所有权分别保存，未解决的 finding 不能随清理丢失。

## 期限、失败与重试

设置与评审规模相称的执行期限，保留运行标识和可检查的进程状态。等待超时不等于 reviewer 已停止；重试或改用替代方案前，取消并等待原运行及子进程退出，确认它们不会继续写结果。

先查看失败信息，区分工具、认证、执行中断和不完整结果。对可恢复的失败或必要结果缺失，在既有权限、期限和重试预算内完成必要重试或等价独立评审，补齐当前输入的必需覆盖。累计同一输入的尝试，不能反复重跑直到得到批准；只重跑失败或受修改影响的评审视角。

Fallback 使用相同输入范围和结果合同，并如实报告实际使用的工具、代理与模型。恢复后核验结果完整性和版本。必要结果仍缺失、不完整或不符合必需标准时，保持评审未完成，继续其他可独立完成的已授权核查；只有确实无法恢复或缺少必要输入、授权时，才以具体缺口结束并说明最小所需条件。评审完成不要求 reviewer 修改被审设计。
