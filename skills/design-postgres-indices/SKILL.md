# 设计 PostgreSQL 索引

## 梳理查询访问路径

- 阅读应用实际执行的 SQL，或捕获 ORM 生成的 SQL。必要时确认参数类型和预备语句的执行行为。检查项目的目标 PostgreSQL 版本、表结构、约束和已有索引。
- 对范围内的每条查询，确认等值条件、连接条件、范围条件、排序键、分页方式和预计返回行数。查询频率、表规模、数据倾斜和写入频率会影响决策时，记录预期值及其依据或假设。
- 将可以共用索引的查询归在一起。检查已有索引支持哪些访问路径，包括为主键和唯一约束提供支持的索引。

## 选择候选索引

- 普通等值查询、范围查询和有序访问优先考虑 B-tree。用索引前导列上的等值条件缩小扫描范围。多个列总是同时有等值条件时，根据其他查询可复用的索引前缀确定列顺序。检查后续过滤列或排序列前面是否存在无约束的列，以及它们对扫描和排序的影响。
- 需要按索引顺序读取时，核对排序列、方向和 NULL 的位置，先检查已有 B-tree 的正向或反向扫描能否满足排序。反向扫描会整体反转方向和 NULL 的位置；混合方向的多列排序仍要检查各列的组合。稳定分页需要消除排序并列时，加上能确定顺序的排序键。范围条件和排序使用不同列时，比较两种路径。一种先缩小扫描范围，再对匹配记录排序。另一种按结果顺序扫描并逐行过滤，达到 `LIMIT` 后停止。结合数据倾斜判断两种路径各会扫描多少行。
- 说明哪些列能限定扫描范围、哪些条件仍需过滤，以及索引能否提供查询所需的顺序。查询能否使用索引存疑时，检查操作符、类型和表达式是否匹配。
- 查询集中在一部分记录且可用稳定谓词定义该子集时，考虑部分索引。确认规划器能证明查询条件蕴含该谓词，相关时也要检查预备语句的通用计划。当减少回表的收益有望抵消索引变宽和写入维护的成本时，考虑 `INCLUDE`。根据操作符和数据的物理布局选择适用的专用索引类型。
- 评估重叠索引时，核对所有相关调用方、约束语义、索引谓词、排序和索引大小。新增索引的预期收益较小时，复用已有索引或保留顺序扫描。

例如，查询一个租户的全部订单并按 `created_at DESC, id DESC` 排序，可以用 `(tenant_id, created_at DESC, id DESC)`。加上 `status = $2` 条件的列表也能复用该索引，在扫描时过滤状态。如果按状态筛选是重要访问路径，而复用索引需要扫描过多记录才能填满一页，可以增加 `(tenant_id, status, created_at DESC, id DESC)`。当 `status` 无约束时，第二条索引会先按状态组织记录，因此无法直接提供该租户跨状态的时间顺序。

## 在开发环境验证

- 使用隔离的开发或测试 PostgreSQL 实例，优先使用与目标环境相同的主版本。准备足量数据，使验证能体现扫描路径的差异。复现相关分布，例如大小租户、常见和稀有状态、窄和宽的范围，以及过滤列与排序列之间的相关性。导入数据后运行 `ANALYZE`。
- 用应用实际执行的 SQL 和有代表性的参数，通过 `EXPLAIN (ANALYZE, BUFFERS)` 对比基线与候选方案。检查实际行数和估算行数、扫描条件、过滤、排序、缓冲区命中和读取，如果 `INCLUDE` 的收益依赖少回表，用能反映实际更新情况的数据检查 `Heap Fetches`；索引只读扫描能否省掉访问堆表还取决于页面的可见性。在可比的缓存条件下对比耗时。遇到明显的行数估算偏差时，先调查原因，再判断计划变化是否由索引带来。对有副作用的语句，仅在可丢弃的数据上实际执行并测量。
- 索引维护成本可能改变决策时，测量索引大小和写入吞吐。记录 PostgreSQL 版本、数据规模和分布、参数及相关执行计划结果。本地实测结论适用于这些验证条件。
- 无法使用隔离的 PostgreSQL 实例时，给出有依据的候选方案和可复跑的验证步骤。说明哪些假设可能改变建议，以及还缺哪些测量。

## 规划索引迁移

- 在已有大表或持续写入的表上，单独评估增删索引的部署影响：构建或删除期间的锁与写入影响、构建成本，以及新旧访问路径的切换顺序。空库迁移跑通只验证 DDL 能执行，部署影响需按代表性数据量和负载评估。
- 普通 `CREATE INDEX` 在构建期间会阻塞表写入。需要减少写入阻塞且适合使用 [`CREATE INDEX CONCURRENTLY`](https://www.postgresql.org/docs/18/sql-createindex.html#SQL-CREATEINDEX-CONCURRENTLY) 时，确认迁移工具支持在事务块外执行，并明确如何识别和处理失败后可能留下的无效索引。

交付时列明目标查询、建议的 DDL 或复用决定、索引列顺序的依据、验证结果及待验证的假设；涉及已有表的索引迁移时，说明上线条件、风险与恢复方式。
