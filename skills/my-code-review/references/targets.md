# 目标与快照

## 本地改动

先读取仓库状态和差异清单，区分已提交、暂存、未暂存和未跟踪内容。尊重用户指定范围，普通 diff 不包含未跟踪文件。

| 目标 | 比较与实际输入 |
|---|---|
| 仅暂存、下一次提交 | `git diff --cached`，读取 index 中的内容，如 `git show :<path>`；工作区可能另有未暂存改动 |
| 未暂存 | `git diff` 比较 index 与工作区；范围涉及的新文件另行检查 |
| 最终未提交状态 | `git diff HEAD` 加范围内未跟踪文件，读取最终工作区内容 |
| 指定提交或区间 | 固定起止提交，读取目标提交中的文件，不混入当前工作区 |
| 分支已提交改动 | 固定目标 head 和正确比较分支，使用 merge-base 到该 head 的明确双端比较 |
| 明确的全文件或模块审查 | 按指定版本或当前快照检查，并声明没有将既有问题归因为某个 diff |

整体最终状态不是暂存与未暂存层次的完整记录；若审查还包括下一次提交的内容，分别读取两层。没有 HEAD 的新仓库使用空基线，仍检查 index 和未跟踪输入。

可用 `git ls-files --others --exclude-standard -z` 枚举未跟踪文件，再按目标选择，排除工具缓存、构建产物和敏感本机配置。显式包含的新增文件不能因不在 diff 中而漏掉。

## 分支与 PR

尊重用户给定的准确提交；普通比较分支核对它的实际上游和更新情况，不把落后的本地基线当成当前合并目标，也不误用功能分支自己的上游。必要时获取目标远端对象，记录实际选择的 ref 与 SHA。

已提交分支使用 `git merge-base <comparison-ref> <review-head>`，再比较 `git diff <merge-base-sha> <review-head-sha>`。单端 `git diff <merge-base>` 会读到工作区，不适合声称只审查已提交分支。多父提交明确所审父提交或合并结果；历史浅缺失或对象不可读时报告缺口。

PR 核对宿主、仓库、编号、目标分支、实际 head 仓库或 fork，以及 base/head SHA。按平台的合并基线差异和固定 head 读取，不能把 base tip 与 head tip 的直接差异当作同一含义。

核对完整文件清单、分页、被截断或省略的 patch、二进制和重命名内容。摘要或局部 patch 不等于完整 diff；必要时通过准确 Git 对象或完整文件补齐，不能静默缩小范围。

## 保持输入与用户工作不变

不要为了审查而切换、reset、stash、clean、rebase 或 merge 用户的工作目录。需要运行会写入的验证时，使用忠实的隔离快照并遵循项目工作区规则；暂存审查使用 index 候选，本地审查保留选定的未提交、未跟踪、删除及相关文件属性，单独检出 HEAD 不足以复现它。

记录实际审查和验证的输入。报告前以及发布前重新核对目标是否改变；基线、head 或本地内容改变时重新评估受影响的结论与行号。保留旧快照结论时明确其版本，不能换个提交名就宣称已审新版本。

命令语义参考当前 Git 帮助及 [git diff](https://git-scm.com/docs/git-diff)、[gitrevisions](https://git-scm.com/docs/gitrevisions)；远端字段、分页与行号参数使用当前平台工具的实际 schema。
