# 移交核对与写入要求

## 内容与责任

先读取选定普通 Task 的完整资源，保留准确版本、Parent、`assignedTo`、状态、权限、平台、依赖及 Worker 记录。终态 Task 直接报告实际结果，不继续查找工作或做无必要的责任查询；其他任务再读取所需材料，并核对当前所属关系与授权范围。

按当前阶段核对任务目标、范围、输入、成果归属与完成条件，包括仓库要求的独立材料交付、审查或验收阶段及其真实前置。实施任务还需有选定方案、必要详细设计、实施步骤、验收和符合项目要求的粒度；讨论或研究任务可以产生未来的规格、方案或报告，不要求产物在启动前存在。不能把缺少定义的实施任务改称研究任务绕过检查。先核实已有来源；对尚未开始、许可关闭且既有准备授权覆盖的任务，补齐可由确认材料确定的内容并读回。未决设计、不可读来源或不一致的交接仍是具体缺口，主动提出必要问题、可选处理与建议，继续核对其他已指定且不受影响的任务。许可已开启或已有执行的任务仍只读核对。

验证或验收任务按 [移交与启动检查](../../plan-actionable-verification/SKILL.md#区分规划移交与启动) 核对候选版本、执行环境能力，以及输入的提供者、取得方式、就绪判据和实际依赖。未来产物可由明确的前置任务提供；无法落实的关键条件作为移交缺口，不能留给 Worker 临场解决。实际启动验证前，由执行者在运行环境核对所需输入可用。

独立确认当前服务上已认证账号的本地用户 UUID，再与非空 `assignedTo` 比较。显示名、邮箱、任务自己的负责人字段或 Worker 记录不能证明当前身份。身份未知、不匹配或任务不可读时，不启用权限，不自行重新分配。核对责任时不为此枚举其他任务集合。

权限已开启的任务可能正在执行，核对不意味着暂停。保留活跃或已释放 Worker 的归属和历史，不恢复旧 claim、工作目录或原生会话。

内容充分与调度就绪分别判断。前置任务尚未完成不必自动阻止移交，但方案与交换约定必须已定义，未来产物不能冒充已有输入。核对 Parent 的状态及当前产品调度限制，不改变 Goal 或 Task 状态绕过它们。

## 按观察状态处理

| 状态 | 操作 |
|---|---|
| `proposed` | 保持状态与权限；进入 `todo` 需要明确的调用者决策，启用权限本身不能使其可执行 |
| `todo`、权限关闭、内容与责任通过 | 用最终审阅的准确版本启用 `allowAgents`，然后核对 |
| `todo`、权限关闭、任一核对失败或未确认 | 保留负责人和权限，按内容核对要求补查或提出必要问题，继续核对其他已指定任务 |
| `todo`、权限已开启 | 只读核对，不重复写 `true` 充当评审标记 |
| `in_progress`、权限关闭 | 报告权限锁定，不改变状态绕过限制 |
| `in_progress`、权限已开启 | 只读核对并报告，不暂停、停止、转移或重新分配执行 |
| `done` / `cancelled` | 报告终态，无需派发或重新打开；取消不证明已交付 |

## 准确版本与结果核对

写入前重新读取最终任务及需要的可变材料，核对当前责任和内容。使用该决定所依据的精确 `version`；CLI 更新显式提供 `--if-version`，保留整数全部位数。版本或负责人改变时重新判断，不能自动换成最新版本重放旧决定。

只更新当前授权需要的字段。移交步骤不改变被移交任务的负责人、Parent、状态、平台、依赖或 Worker 历史；必要准备和前置阶段收尾按各自的授权和完成条件处理。附件内容不受 Task 版本冻结，需单独核对。

检查响应，再读回完整任务与必要材料。Worker 可在许可开启后立即 claim，版本增加或进入执行中不表示写入失败，不能因此重试。

超时、取消或响应丢失不等于回滚。沿用原资源和操作上下文核对实际状态，区分确认响应与观察结果；仅观察到权限为真不能证明由本次操作开启。

写入后若内容或责任核对失败，报告实际负责人、权限和仍可能调度的事实，不宣称成功派发，也不自动撤销权限或停止执行；这些需要另行授权的管理操作。未解决的不确定结果保留为缺口，不盲目重试。

## 结束条件

只有内容与责任核对通过，且所需写入及最终状态已确认，才报告成功派发。原本已有权限的任务说明本次只是核对。报告版本、负责人、平台、权限、状态、依赖阻碍和适用的 Worker 归属，然后返回，不把执行许可当作启动或交付证明。
