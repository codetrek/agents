# 移交给Agent自动执行

将用户指定且符合条件的已有任务交给 Worker：核对内容和认证责任，启用执行许可并读回后返回。许可开启不证明执行已经启动或交付完成。

## 确定已有目标与授权

沿用当前请求和已有授权，确认用户要求移交的 Task、固定清单或 Goal，以及实际 Project。读取任务或编辑这个 skill 不自动授权移交。使用当前 CLI 或 MCP 的手册与 schema，遵守目标项目的阶段、材料和写入约定，不重复询问已有授权。

单个 Task 只检查该对象和真正需要的来源，不扩大为整个链或 Goal。固定清单逐项处理，不选择更多工作。

指定 Goal 时按 [dn-goal](../dn-goal/SKILL.md) 核对实际身份与成员；本次只枚举其全部未完成普通直接子任务及所有页面，逐项核对实际 Parent。不能用依赖连通性、标题前缀或 progress 计数代替清单，也不把跨 Goal 或无 Parent 的前置加入移交范围。空 Goal 无任务可移交，失败读取不能当作空集合。

Goal 状态不替代子任务状态，也不能用于自动接受 `proposed` 子任务。Goal 自身不交给 Worker；Goal 的负责人不代表有权改变其他账号的 Task。

## 内容、责任与状态核对

按 [移交核对与写入要求](references/checks-and-write.md) 读取完整定义和必要材料，独立确认当前认证账号 UUID，并与 Task 的非空 `assignedTo` 比较。未知身份、分配不匹配或缺少必要材料时，不启用许可、不自行重新分配。

核对任务自身阶段的完整定义。实施任务参考其已确认设计与 [plan-reviewable-changes](../plan-reviewable-changes/SKILL.md) 的边界要求；已有输入与未来输出分别表达。缺口按参考要求先核实，既有准备授权覆盖且任务状态允许时补齐并读回。实质需求、设计或粒度确需决定时，明确受影响项、具体问题与建议，交回相应准备流程，并继续核对指定清单内不受影响的任务。移交不重做架构、重分任务或修改依赖。

`proposed` 保留状态和许可，明确接受并选择 `todo` 的准备变更按已有授权先完成、重新读回；移交请求本身不等于接受提案。许可已开启或已有执行的任务只读核对，不假定 Worker 已暂停。

## 启用并核对

只有 `todo` 且许可关闭、内容与责任核对通过的任务，才用最终审阅的准确版本启用 `allowAgents`。其他状态按参考文件的规则处理；移交步骤不改被移交任务的负责人、Parent、状态、平台、依赖或 Worker 历史。

写入前后核对实际任务和所需可变来源，附件不受 Task 版本冻结。版本、责任或内容改变时重新判断；许可开启后 Worker 立即 claim、版本上升或进入执行中不意味着操作失败，不能因此重试。

超时或响应丢失先核对实际状态，保留原操作上下文，不盲目重放，也不把匹配现值当作本次写入的证明。写后核对失败时报告实际许可和仍可能调度的事实，不自动撤销、停止或转移执行。

## 报告并返回

逐项返回引用、内容与责任结论、确认修改或具体缺口，以及实际版本、Parent、负责人、平台、许可、状态、依赖阻碍和适用 Worker 归属。只读核对、确认写入和结果不确定分别说明，一项通过不代表清单或整个 Goal 都通过。

完成所需核对后返回，不等待 claim、不启动本地实现、不发送执行消息。移交本身不完成被移交任务或其 Goal；同一请求中的前置阶段收尾按各自的授权和完成条件处理。普通移交不恢复旧 claim、工作目录或原生会话，也不开展未经授权的管理操作。
