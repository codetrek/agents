# 调查缺陷并派发Daynight修复任务

当前会话负责查明问题、确定修复方案及准备完整任务，Daynight Worker 负责实现、验证和约定交付。主动推进到派发核对完成，不把未决根因或关键设计隐含交给实现者。

## 确认范围与仓库流程

明确要求用本 skill 处理具体 bug 时，在所指定范围内连续完成调查、任务准备、登记和 Worker 移交，沿用已有授权；明确只要求调查、讨论或登记时遵守该限制。创建、编辑或讨论本 skill 不启动实际缺陷处理，也不授予本地实施、PR 合并或部署权限。

读取用户报告、目标仓库及适用目录的指示，按其缺陷、设计、任务、PR、审查与验收流程及已有例外推进。需要预先交付修复设计、独立验收或维护原生 Issue 时纳入实际阶段与依赖；覆盖当前范围的已接受成果直接复用。确需或已属于 Daynight Goal 时按 [dn-goal](../dn-goal/SKILL.md) 组织，不为每个 bug 机械创建 Goal 或重复设计。

按 [dn-use](../dn-use/SKILL.md) 确认实际 Project、查找同一问题的已有工作并读取完整定义和必要来源。保留任务身份、责任与执行归属，不接管活跃执行或重复建项绕过它。独立调查或设计阶段按项目要求跟踪；读代码、命令、试验、内部调研轮次和代理分工留在 Session。

## 核实问题与根因

明确触发条件、实际与期望行为、影响对象、相关版本、输入及环境。依据已确认需求、公开约定和真实调用者判断问题；用户报告的归因、当前实现或已有测试都不能单独证明根因。行为要求存在实质歧义时主动提出具体问题与建议，继续不依赖该决定的调查。

沿实际调用、数据、状态与生命周期追查失败机制，按问题委派研究代理并独立核对关键证据。先形成可区分的假设，再通过复现、日志、代码和针对性试验验证因果关系，分清观察、假设、已排除解释、确定结论和剩余缺口。不能仅凭可疑代码、异常附近的位置或一个看似有效的 patch 宣称找到根因。

尽可能在隔离环境构造能触发原失败机制的复现，记录适用版本、必要输入、操作与预期结果。调查需要的探针与试验遵守操作授权、仓库工作区和资源清理约定，保留原始状态与他人的修改，不直接改动生产数据或服务。

无法本地复现时，核对故障版本、真实记录和运行条件，以确定性代码证据或其他独立依据验证解释，并明确未实际验证的行为。不把未复现当作没有问题；证据不足以选择可靠修复时继续调查，确需外部输入时提出最小所需条件，不把猜测写成必需实施方案。

## 确定修复与验证方案

选择消除已验证失败机制的修复，说明修改位置、选定机制、必要设计、实施顺序、调用者影响和必须保持的契约。正常代码阅读、局部编码选择、实施调试仍由 Worker 完成，不要求逐行代码指令。

按 [write-layered-tests](../write-layered-tests/SKILL.md) 确定验证：覆盖原故障和重要正常、失败、边界及适用并发行为。能够自动化时明确回归用例在原实现中的失败依据及修复后的预期；不能自动化时说明等效验证及限制。不能用放宽断言、吞错、反复重试或绕过真实故障边界充当修复。

规模与交付边界按 [plan-reviewable-changes](../plan-reviewable-changes/SKILL.md) 核对。小而完整的修复保持聚焦；涉及重要契约、多阶段或实质设计选择时，按仓库要求使用 [my-architect-and-design](../my-architect-and-design/SKILL.md) 完成必要方案与确认，再登记交付拆分。新增能力和无关清理不混入修复，实质范围变化交由用户决定。

## 保存完整任务并移交

任务与必要引用应让没有原会话的 Worker 独立实施，包含现象与影响、期望行为、根因及证据、修复范围与选定方案、必要设计与有序步骤、可读来源及版本、回归验证和交付完成条件。正式材料保存在实际所有者，仓库文档遵守位置与生命周期；Goal 的共享结论按其归属同步，证据不能只指向私有临时路径。

符合小任务边界时，使用 [dn-dispatch-small-task](../dn-dispatch-small-task/SKILL.md) 完成准备、登记与派发。已有确认的多项交付拆分使用 [dn-create-delivery-tasks](../dn-create-delivery-tasks/SKILL.md) 登记当前阶段允许创建的任务，再按 [dn-handoff](../dn-handoff/SKILL.md) 移交指定合格任务。架构及仓库必需阶段的实际前置、材料引用和 Parent 分别核对，不能用引用代替执行依赖。

先保存并完整读回任务和必要材料，新建任务先保持执行许可关闭，通过内容、独立认证的责任与状态核对后才用准确版本启用。许可已开启或已有执行的任务只读核对；发生冲突或不确定写入时按原资源与操作上下文查明实际状态，不盲目重复创建或派发。

## 结果与结束条件

可由现有材料、调研或验证解决的缺口主动补齐；必要决定提出具体问题、影响与建议，同时完成不依赖该决定的准备。必需来源、身份或工具不可用时如实保留缺口，不用不完整实施任务冒充已派发；查明无实际缺陷或问题已由现有交付解决时，给出证据，不制造重复修复。

返回根因结论及证据、修复和验证方案、真实任务与材料引用、确认写入或只读核对结果、实际状态与剩余限制。派发并读回后返回，不等待 claim、不在本会话接手实现；已派发不表示已经实现、合并或修复目标环境，修复任务不因此标为完成。持续监控或驱动整个 Goal 由用户明确要求或已经激活的上层流程承担。
