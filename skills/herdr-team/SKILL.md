# Herdr 团队模式

仅在用户手工启用时进入本模式。Leader 专门负责协调，teammates 负责具体任务执行。讨论、创建或读取本 skill 不代表激活团队。

## 激活与环境检查

每次手工激活后的第一项操作是运行 `herdr --skill`，完整读取当前手册，然后检查 `HERDR_ENV=1`。

命令失败或环境检查不通过时，立即提示当前不在可用的 Herdr 环境中，并结束本次初始化；不读取或控制外部 Herdr 会话。

通过检查后，绑定调用者当前 session、workspace、tab 和真实 pane 身份。使用明确的 ID 和实际布局，不依赖界面焦点、侧栏顺序或示例编号。

## Leader 与团队布局

只由当前 tab 最左侧的 Agent 手工激活并担任 leader，不另行启动第二个 leader。

Leader 负责理解目标、准备完整任务、分工与依赖、进展监控、阻碍处理、成果汇总和验收。具体调查、实现、测试和审查工作交给 teammates。

Leader 可以在当前 tab 的右侧按需创建最多四名 teammate，形成右侧 2×2 田字格布局；全队最多五名成员。启动中、等待中、阻塞中以及尚未确认退出的队员都计入上限。

优先复用本团队的已有成员，保留其他 pane 和工作现场。后台布局操作保持用户焦点；工作目录与工作区按当前任务和仓库约定使用，不为每名队员重复建立工作区或安装依赖。

## Codex 启动与模型指定

所有 teammate 均使用 Codex 启动，无论 leader 使用哪种 Agent。

每次启动 teammate，leader 必须选择当前可用、符合任务要求的 Codex 模型，并在本次启动配置中显式传入。用户已有模型要求时优先遵从；否则由 leader 根据任务复杂度、约束和成本自主选择。

不能依赖未核对的默认模型，也不能用队员名称、任务提示词或口头声明代替实际模型配置。记录队员身份、pane、所选模型和启动结果；确认真实 Agent 已就绪后再派发任务。

启动失败、超时或状态不明时先核对实际状态，不能立即重复创建或启动。

## 委派完整任务

每次派活都给出一个完整、可独立推进的任务，深度随任务规模调整，至少明确：

- 背景、目标和需要解决的问题。
- 本次范围、职责边界及必须保持的行为。
- 已确认方案、必要输入、真实来源与适用版本。
- 实际工作区、仓库规范、允许修改的内容和操作授权。
- 前置依赖、协作关系及时间或资源约束。
- 预期成果、验证方式、验收条件和交付终点。
- 完成或阻塞时应向 leader 返回的结果、证据与具体缺口。

可以引用现有的完整任务材料，但不能只给模糊方向、无解释的链接或“看之前聊天”。实施所需的关键决定尚未确定时，先补齐或明确组织相应讨论，不把未决设计隐含交给实现者。

Teammate 收到任务后，在范围与权限内自主推进到约定结果；常规实现选择自行决定，不逐步骤等待 leader 指示。确需决策或外部介入时，提出具体问题、影响和建议，同时完成不受影响的工作。

队员完成或真正受阻时向 leader 汇报。需要额外协作者时由 leader 统一安排，队员不自行扩充团队。

## 每十五分钟巡检

团队激活后，leader 建立每十五分钟一次的真实定时唤醒与巡检，绑定本次团队和同一 leader 的执行上下文。

巡检检查所有队员的实际状态、任务进展、最新结果、明确等待对象、阻碍及下一步。发现结果、错误或决策请求时及时处理，不必等到下一个巡检周期。

定时巡检不重新初始化团队、不重复创建队员，也不启动另一名 leader。重复触发应合并，避免重叠巡检；单个队员的长时间等待不能阻断全队检查。

只有定时机制实际建立并可用，才能报告巡检已开启。暂停、退出或失去有效团队上下文时，停止相应定时推进并核对已有执行的真实状态。

## 久无结论时主动诊断

Leader 持续等待并核验任务结果，不以 Agent 的 `idle`、`done` 或在线状态代替成果验收。

按任务预计耗时、阶段和已有进展判断是否需要调查。长时间没有结论或没有可解释的进展时，主动核对任务是否真正开始、资料是否充分、是否遇到错误、审批、输入、依赖、环境或权限问题。

根据查明的原因补充信息、协调依赖、提出必要决策或按授权恢复，同时推进其他不受影响的任务。协调消息要说明具体问题和预期结果，不以反复发送“继续”代替诊断。

正常长操作或有明确对象的外部等待不自动判为停滞；超时或观察缺失也不证明任务失败、未启动或已经完成。保留原执行身份，不盲目重发、不接管或强制重建执行。

## 权限、验收与退出

团队初始化授权不自动扩展为代码修改、PR 发布、合并、部署或破坏性操作。各任务沿用用户及上层流程已有的实际授权，遵循目标仓库规范。

Leader 核对每项任务的真实成果、验证和约定交付条件，汇总完整目标的结果与剩余工作。派活、启动成功、收到回复或全部队员空闲都不等于目标完成。

任务结束后可复用队员等待新的授权工作，不自行选择额外目标。用户暂停或退出团队模式时，停止新增派发并清理本模式拥有的定时与监控资源；已有任务按明确指示和管理权限处理，保留未交付工作及其他人的资源。
