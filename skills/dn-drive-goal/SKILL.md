# 持续推进 Daynight Goal

Driver 负责将 Goal 的已确认设计拆解为可独立执行的任务或任务链，交给 Daynight Worker 自动执行，持续监控整体进展、处理错误与阻碍，并确保 Goal 按设计交付和通过整体验收。Worker 负责具体任务的实施与交付；单项任务或内层 skill 完成后，Driver 接续下一项必要工作，直到目标实际完成。

## 激活与范围

仅在用户明确要求持续推进一个实际 Goal 时激活；创建、编辑、讨论或提及本 skill 不代表激活。确认 Project、Goal、目标范围和完成条件，沿用已有确认与执行安排。

明确激活构成该 Goal 范围内的持续交付授权：Goal 状态与材料维护、必要任务登记、Worker 移交、执行协调及必要审查沟通、验证、PR 发布与反馈处理，以及满足目标仓库和当前会话适用的验证、CI、审批与交付条件后的合并。后续复用授权，不逐任务重复确认。项目规定的需求、架构及实质范围变更确认点仍须满足；部署、跨 Goal 工作、强制释放或转移执行、重分配及破坏性管理操作需独立明确授权。

在当前对话及其恢复后保持激活，状态询问不停止推进。用户暂停、停用或调整目标时遵从最新指示；暂停时停止新增推进，按明确指示及管理权限处理已有执行，报告实际暂停范围。完成这个 Goal 后结束本次驱动，其他 Goal 需要新的明确目标。

## 全程遵循目标仓库规范

以各任务实际执行的仓库和版本为准，读取根及适用目录中现有的 `AGENTS.md` 等仓库指示，以及必要工作流、代码组织、测试、文档、Git/PR 和验收规范。将这些要求落实到整个 Goal 的阶段确认、任务拆分与登记、Worker 执行、监控恢复、交付、验收和清理，不只在启动时读取一次；切换阶段、工作区或相关规范变化时重新核对适用要求。

目标仓库明确规定的开发流程、PR 规范和已有例外，优先于本 skill 的通用流程。按 [dn-goal](../dn-goal/SKILL.md) 将适用阶段、成果、前置、材料生命周期和完成要求落实到整体方案与子任务，复用有效成果，按授权补齐必要独立阶段。

按用户明确要求与已有授权处理实际冲突，不重复请求已有授权；未明确的实质冲突主动提出具体问题，继续不受影响的工作。持续交付授权不能替代规定的确认点、质量检查或交付条件。必需规范不可读或其适用版本无法核实时保留具体缺口，不当作没有规范或可以豁免。

## 恢复上下文并维护 Goal

按 [dn-goal](../dn-goal/SKILL.md) 的组织、材料、状态与验收要求，读取实际 Goal、共享来源及全部直接子任务，核对完整成员与剩余范围；CLI、MCP 和状态语义以当前产品手册及 schema 为准。

恢复各 Task 的负责人、状态、许可、平台、依赖、Worker、claim、PR 与验收事实，先观察再行动，保留资源身份和已有执行归属。驱动开始、等待、恢复及阶段结果变化时，协调者负责主动核对并维护 Goal 状态；服务已自动启动 Parent 时先读回，不重复写入或重启区间。暂停驱动不自动取消 Goal，终态恢复仍需明确授权。

## 循环推进当前目标

1. **补齐当前阶段。** 缺少完整需求或架构时，按项目确认点组织 Worker 产出，采用 [my-write-spec](../my-write-spec/SKILL.md) 或 [my-architect-and-design](../my-architect-and-design/SKILL.md) 的要求核对材料；已有执行负责该阶段时保持其产出与执行归属。能由确认材料确定的缺口先查证、补齐；实质决定提出具体问题、选项、影响与建议，同时完成不依赖该决定的工作。评审、状态或执行许可不能代替用户确认。
2. **拆分为可执行任务或任务链。** 依据已确认设计，明确各项任务的独立成果、范围、输入、方案、约束、验收和交付终点，并按真实前置组成任务链或安排可并行的任务。仓库未规定的部分优先使用 [plan-reviewable-changes](../plan-reviewable-changes/SKILL.md)，已有规定的部分在满足仓库规则的前提下结合使用；复用仍适用的确认拆分，按项目要求完成必要确认。实施、仓库必需的独立阶段交付及整体验收都有承接，内部执行动作留在 Session。
3. **登记并自动移交。** 按仓库阶段创建或复用当前允许且定义完整的未完成任务，核对材料、Parent 和实际依赖图。交付方案与拆分已确认时使用 [dn-create-delivery-tasks](../dn-create-delivery-tasks/SKILL.md)；讨论、调研或方案生产任务按自身阶段登记，不要求其未来产物在启动前已经存在。新建任务先保持执行许可关闭，完整保存并读回后，由 Driver 接着调用 [dn-handoff](../dn-handoff/SKILL.md)：通过内容、独立认证的责任与状态核对后，用准确版本启用 `allowAgents=true` 并核对结果。持续驱动授权已覆盖这一移交，无需用户逐项再次派发；不能因登记 skill 已返回，就把任务留在仅登记状态。未确认提案不自动接受，不合格项明确缺口并继续处理其他合格项，已有许可或执行在移交核对时保持只读。
4. **跟进交付并关闭任务。** 按各 Task 原定范围持续核对成果、所需 PR、CI、审查和验收；自身完成条件满足后立即收尾、提交完成并读回，不等整个 Goal 结束，也不把新工作当作继续保留原 Task 的理由。已有 Worker 负责的实现与交付保持其归属，避免重复执行或重复合并；协调者办理交付操作前核对分工与实际状态。Worker 完成使用原 claim 和合法执行身份，不能用普通状态写入绕过 claim 完成要求。
5. **重新核对剩余工作。** 成果或依赖变化后，检查后续任务、仓库必需阶段、必要集成、消费者采用和整体验收是否已有承接。新工作另建完整 Task，或匹配已有的未完成后续任务，登记并读回后再移交；不得重用已完成 Task 来承接。没有就绪任务时检查正在执行、等待交付、前置阻碍、缺失定义或未登记的必要工作，不能直接结束 Goal。只补齐当前确认范围内的必要工作，实质范围变化交由用户决定。

任务链的执行许可与调度就绪分别核对：方案、契约与任务定义完整的后继，可以先完成自动移交，由真实依赖约束何时启动；未完成前置的产物不能冒充已有输入，调度允许的 cancelled 前置也不证明输入存在。每轮恢复、创建或补齐任务后，检查 Goal 内尚未移交的合格任务并完成移交，不能只监控已经运行的任务。执行前置不满足时不虚构开始状态，外部前置不自动进入本 Goal 的执行范围。

遇到“部署后才能 E2E”这类等待时，先按 [验收对象与环境](../plan-reviewable-changes/SKILL.md#代码验收的对象与环境) 核对：代码验收应由执行方在受控环境构建并启动指定版本。纠正把线上发布误设为前置的定义；真实缺少的版本、配置、数据或环境准备责任需具体说明并在授权内补齐，不能让验收无限等待无人负责的部署，也不能据此自行触发生产操作。

委派时向 Worker 传递完整任务、实际工作区、适用规范的可读入口和必要约束，由其读取完整的适用规范；协调摘要不能代替仓库原始指示，操作与协作约定留在执行上下文。移交核对返回后继续观察真实启动、执行与交付，执行许可开启不证明 Worker 已开始或已完成任务。

办理 PR 合并前，重新核对当前 HEAD、适用的验证与 CI 结果、实际要求的审批、未解决线程与可合并性，满足仓库及当前会话要求后按允许的方法将合并绑定到已验证的提交。HEAD 改变后重新判断；持续交付授权不允许绕过审批、检查或保护规则。

## 完成后的新工作使用新 Task

按 [dn-goal](../dn-goal/SKILL.md) 保持单项任务边界。每次向 Worker 发送工作前，核对本次内容属于哪个 Task，以及该 Task 是否已完成原定范围。已完成或仅待完成状态同步的 Task，只处理原成果核验与关闭；不能追加新指令、扩大描述、沿用旧执行身份，或为继续派活自动重开它。

后续工作先有自己的任务身份、范围、方案、来源和验收，按仓库阶段及创建授权登记，再通过 `dn-handoff` 核对和移交。执行承接遵循新 Task 的正式分配与执行身份，不能直接给旧 Task 的 Worker 或 Session 发消息代替新任务移交。关闭写入失败或结果不确定时先核对实际结果，按原执行合同补齐尚未完成的关闭，不盲目重放，也不能把尚未关闭当作继续加活的许可。

原 Task 的必需验收或交付仍未通过时，继续在原范围内修正并验证；已完成后的新发现按新 Task 处理。持续推进 Goal 通过承接后续任务实现，不通过不断延长一个 Task 实现。

## 持续监控执行中的任务

维护该 Goal 内全部已有执行或状态为 `in_progress` 的任务监控清单，包含已有 Worker 和其他负责人的任务，不只检查新移交或当前选中的任务。按当前手册核对真实 Worker、Session、执行身份及观察的新鲜度；任务状态不能证明执行健康，心跳或连接在线也不能证明工作正在推进。

每项任务同时观察执行与实际进展：当前活动、必要 Session 内容、阶段成果、PR 提交、CI 或审查变化，以及明确的等待对象与下一步。最近有效观察、当前阻碍和下次检查条件保存在 Session checkpoint；陈旧、缺失或失败的观察保持未知，不能判成健康或停滞。

按任务阶段、预计耗时和异常风险选择有界监控间隔，正常长操作与明确的外部等待减少无效查询，异常或变化后及时复查。发现失败、失联、需要输入或持续没有可解释的进展时，主动核实原因，按授权恢复或提出具体介入要求，同时推进其他不受影响的任务；不能仅把异常记录后继续被动等待，也不按统一的无输出时长自动停止或重建执行。

必要协调消息依据当前执行身份、发送条件和已有授权，说明要解决的问题与预期结果；不以反复发送“继续”代替诊断。监控同时核对执行与成果是否符合设计及适用仓库规范，偏离时核实原因，按任务原范围协调 Worker 修正并复核；需要独立承接的新工作按新 Task 登记并自动移交，实质设计变化走项目确认点，同时继续不受影响的工作。任务完成或执行变化后，核验实际成果与规定的交付条件，再更新监控清单、Goal 进展和后续依赖。持续监控不授权接管、重分配或强制释放已有执行。

## 持续等待与恢复

移交完成、许可开启、一次命令结束、空就绪列表和等待超时都不是 Goal 完成。正常执行、CI 或审查等待仍是当前工作；使用有界等待与合理查询间隔，关注变化并处理新失败或反馈。只有实际具备继续执行机制时才声明后台持续观察。

没有实际启动或执行失联时，先核对就绪条件、内容、责任、许可、平台、Worker 可用性和调度限制。按已有权限完成可恢复的处理，不能反复写许可、重建任务或接管旧 claim 代替诊断。CI 失败先看日志，遵守项目累计重试预算；预算耗尽后定位并修复原因，不弱化检查或让 PR 随修复扩大。

写入前使用决定所依据的准确版本；冲突后重新判断。响应丢失或结果不确定时保留原操作上下文并核对实际资源，不盲目重放。等待或中断前保留最小 Session checkpoint：目标与授权、当前工作与资源身份、PR HEAD、验证及审查状态、累计重试、阻碍和下一步；恢复时重新读取真实状态。

## 成果、整体验收与结束

持续执行 [dn-goal](../dn-goal/SKILL.md) 的共享成果同步、整体进展和验收规则，重要结果、范围或阻碍变化时更新实际所有者并读回。不可读成果、遗漏范围和未验证要求不能抵充完成，继续推进已授权的必要工作；操作、等待、授权和恢复记录留在 Session。

组织并核验完整目标的实际组合成果、必要 PR 合并与适用原生收尾；确认子任务完成合同与整体验收均成立后，保存结论并将 Goal 更新为 `done`、读回。清理本次拥有的临时资源和监控，保留他人的执行与资源，返回 Goal、实际成果、PR 与合并提交、验证证据和必要限制。

仅在 Goal 实际完成、用户暂停或停用，或已证实需要外部介入且没有其他可独立推进的授权工作时交回。未完成时保留真实状态和最小恢复上下文，明确具体阻碍、已完成部分及最小所需条件，不询问是否继续已授权工作。
